# Skill-Anwendung

Ehrliche Übersicht, welche installierten Skills für diese Demo geprüft und wie sie angewendet wurden. Stand 30. Oktober 2026.

- **gelesen** = die `SKILL.md` wurde vollständig gelesen; am 30.10.2026 hat ein Hilfsagent alle 25 Dateien erneut gelesen und einen
  Regelauszug (Zweck, Regeln, Werkzeuge, Konflikte) erstellt, den ich zur Kontrolle dieses Berichts verwendet habe.
- **ausgeführt** = das Werkzeug des Skills wurde tatsächlich gestartet.
- Konfliktregel des Auftrags: `design-taste-frontend` (v2) ist der Standard; die Gestaltung muss zur Kanzlei passen; widersprechende
  Stile werden nicht vermischt; kein Brutalismus wegen eines Skills; keine App-Oberfläche; keine schweren Scroll-Effekte; generierte
  Bilder nie als echte Personen, Mitarbeitende oder Räume.

## Inventar

- Persönliche Skills (`~/.claude/skills`): 14, alle im Auftrag genannt.
- Projekt-Skills (`03_Websiten_hustle/.claude/skills`): 33, davon im Auftrag genannt: `frontend-design`, `ui-ux-pro-max`; zusätzlich
  herangezogen: `frontend-ui-engineering`, `using-agent-skills`, `security-and-hardening`, `code-review-and-quality`.
- Plugin «design»: `accessibility-review`, `ux-copy`, `design-critique`, `design-handoff`, `design-system` (alle gefunden unter
  `~/.claude/plugins/synced/…/design/skills/`).
- Keine Skills installiert, nichts Kostenpflichtiges verwendet.

## Konflikte und ihre Auflösung

| Konflikt | Entscheidung |
| --- | --- |
| Serife: v2 «stark abgeraten», minimalist-ui und high-end sehen sie vor, stitch verbietet Garamond-Familien | Serife ja, weil der Auftrag sie verlangt; Newsreader als Titel-, Randnotiz- und Zitatschrift, Hanken Grotesk für Lauftext und Bedienung. |
| Bewegung: gpt-taste und high-end verlangen Scroll-Animationen, stitch Dauerbewegung; v2 «begründet», frontend-design «weniger ist mehr» | Stufe 2: nur Rückmeldungen (140 bis 200 ms), Menü-Einblendung, kein Scrolltelling; alles aus unter reduzierter Bewegung. |
| JavaScript-Bibliotheken: v2 Motion, v1 Framer, gpt-taste GSAP | keine; nur React/Next, Phosphor-Icons. |
| Bildgenerierung: v2, image-to-code, imagegen-web, brandkit verlangen sie zuerst | keine KI-Bilder (Auftrag); vier belegte Bilder, Rechte offen dokumentiert. |
| Radius: minimalist 4 bis 12 px, high-end 2 rem, stitch 2.5 rem, brutalist 0 | 0 überall (eigenes System, nicht wegen des Brutalismus-Skills). |
| Palette: frontend-design warnt vor Creme + Serife + Terrakotta, v2 verbietet Beige + Messing + Espresso, high-end empfiehlt genau Cremes | warmes Papier mit tiefem Grün als einzigem Akzent, keine Metallic- oder Terrakotta-Töne. |
| Hero zentriert: v1/stitch verboten, gpt-taste bevorzugt | linksbündig mit Bild rechts; Titel in vier kurzen Zeilen (bewusste Abweichung von v2). |
| Eyebrows: high-end Pflicht, v2 höchstens eine je drei Abschnitte | eine Überzeile im Einstieg; Randspalten-Etiketten sind Angaben, keine Dekoration. |
| Cookie-Consent: redesign verlangt ihn | keine Dienste Dritter, deshalb kein Banner; Komponente vorbereitet. |

## Ergebnis der Abschlusskontrolle

- Alle im Auftrag genannten Skills gelesen und zugeordnet; vier bewusste Abweichungen vom Standard-Skill (Serife, vierzeiliger Titel, keine Bildgenerierung, senkrechtes Register statt einzeiliger Navigation) mit Grund.
- Maschinelle Nachweise: `npm run pruefen` (Inhalte, Lint, Typen, Kontraste), Audit 52/52 hell und dunkel, Funktionen 93/93, Lighthouse live
  (`docs/PRUEFBERICHT.md`). Nicht nachweisbar: Screenreader und echte Geräte.
